# Shiori Crimson Hyprland — v0.1.0-beta.1

**Release channel:** GitHub prerelease (experimental). **Status:** candidate prepared; the actual GitHub release must be tagged/published by the maintainer after checks. **Not** Shiori Crimson v3.4 Stable.

## What's included

- Source code for the actual Shiori Crimson HUD, launcher, dock state, power UI and Hyprland/Waybar configurations (Asura baseline v3.3.3.1).
- Local installed-application icon resolution (Gio/GTK) instead of bundled Google Chrome, Discord, Docker or Spotify PNGs.
- Public beta README with two Asura screenshots; originals and artwork have separate personal, non-commercial terms.
- Portable configuration **templates**, with preview rendering, plus a narrowly scoped **fresh-test-account installer** and safe manifest-backed rollback. No automatic startup, package installation, privilege escalation, driver updates, or Hyprland reload.
- Automated source, asset, installer and rollback tests.

## Support level

- **Only a disposable test account, with matching LG display hardware and a recoverable Hyprland environment, is eligible for the optional installer.** Other machines can inspect source, run tests and render previews, but should not attempt live installation.
- The installer never overwrites any pre-existing Hyprland/Waybar/Shiori file; it refuses symlinks and refuses operation inside an active Hyprland session.
- The original HUD/power UI assume an LG monitor and may not start if one isn't available. Some Waybar/Hyprland labels, modes and keyboard settings remain Asura-specific.
- **No deployable Shiori wallpaper assets** are in this release. Supplied screenshots are for documentation, not bundled wallpaper files.
- Real-world spare-account installation and rollback, cross-machine support, GPU/GTK, and login-time responsiveness are **not yet validated**. A passing simulation is not a guarantee.

## Known risks

1. HUD and power UI hard-pin to LG monitor; ASUS local-popup routing is not implemented.
2. Synchronous subprocess media/GPU lookups can temporarily block GTK.
3. Dock-state modules poll every 3 seconds; performance optimization is deferred.
4. Missing/non-installed apps need local icon/theme fallback and runtime testing.
5. Historical `activate.sh`/`restore.sh` are archival developer scripts, not the beta installer.
6. Power actions can cause real logout/reboot/shutdown after user confirmation.

## Maintainer release sequence (only after gates pass)

1. Apply the release-candidate ZIP to a clean repository and run the complete test suite, prepublication scan, source check, image-license review and GitHub Actions.
2. Conduct a **real disposable-account test** of test installation, login and rollback; verify display behavior without modifying daily Asura.
3. Review `git diff`, commit/sign source changes and push to `main` without force.
4. Create a signed annotated tag `v0.1.0-beta.1` **only on the validated commit**, and push the tag after approval.
5. Create a GitHub **prerelease**, *not* a stable release, using this note and archive. Keep this warning visible.

No release or tag is generated by extracting or running the patch ZIP.
